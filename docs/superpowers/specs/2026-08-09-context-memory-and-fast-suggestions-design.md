# 懒狗输入法上下文记忆与低延迟建议设计

**状态：** 用户已批准，2026-08-09 进入实施。

## 目标

把现有“根据输入框草稿猜回复”的演示能力改造成真正依赖当前聊天上下文和会话记忆的回复助手，同时恢复可发布的中文全拼、拼音 9 键与稳定部署。AI 默认开启，但只有在获得聊天上下文权限后才自动生成；用户仍可随时关闭 AI。

## 非目标

- 不在 v1.0.0 热路径中引入完整 OpenClaw 或通用自主 Agent。
- 不后台扫描聊天应用，不上传或落盘截图。
- 不因没有上下文而退化为只根据输入框草稿自动生成。
- 不为每个按键、光标移动或草稿变化重新请求模型。
- 不在首版同步原始聊天消息；端到端加密跨设备同步另行设计。

## 输入与部署基线

Android APK 必须携带并首次部署完整 RIME 数据清单，包括 `default.yaml`、Luna Pinyin、`langou_t9`、`essay`、Emoji/OpenCC 与主题配置。构建生成目录和静态 assets 同时参与 `checksums.json`，从而让 `DataManager.sync()` 把真实中文方案复制到应用私有目录。默认方案为全拼，键盘提供明确的 26 键与拼音 9 键入口；Shift、退格、回车等功能键使用本地化短标签或图标，不显示上游内部键名。

## 运行时架构

### 1. CaptureSession

上下文采集会话仅在以下条件全部成立时有效：

1. 懒狗输入法窗口可见；
2. AI 开关开启（首次安装默认开启）；
3. 当前应用属于支持的聊天应用；
4. 当前控件和窗口通过敏感场景策略；
5. 用户已授予对应系统权限。

Android 11+ 优先使用无障碍窗口截图；UI 节点文本足够时不截图。Android 8–10 使用用户明确授权且仍有效的 MediaProjection。截图只存在内存，OCR 完成立即释放，不上传、不缓存、不写文件。密码、支付、银行、密码管理器与系统安全界面直接清空当前快照和会话采集状态。

### 2. ConversationIdentityResolver

会话身份由应用标识、规范化后的聊天标题/联系人提示和可用的稳定 UI 特征计算。索引只保存带应用密钥的 HMAC，不保存明文联系人作为索引。身份置信度不足时使用仅在本次输入法会话有效的临时 ID，禁止与既有长期记忆合并，以防串聊。

### 3. EncryptedConversationStore

Android 使用 Keystore 中不可导出的 AES-256-GCM 密钥，对 `noBackupFilesDir` 中每个会话的 JSON 记录整体加密并原子替换。每个会话最多保存最近约 100 条去重消息，原始消息最长保留 30 天；同时保存长期摘要、称呼、关系、语气偏好、重要事实和未完成话题。启动和写入时执行 TTL 与条数裁剪。用户可以删除单个会话或全部本地记忆。

云同步默认关闭。用户主动开启后只同步后端应用层加密保存的摘要，不同步最近原始消息；TLS 保护传输。服务器当前仍可为生成请求解密摘要，因此这不宣称端到端加密。真正 E2EE 需要设备配对/恢复密钥，延期到后续版本。

### 4. MemoryRetriever

检测到新的聊天上下文后，先把经过角色分段和去重的消息合并进本地会话，再选择：

- 当前长期摘要；
- 最近的连续聊天轮次；
- 与最新消息关键词/实体相关的较早轮次；
- 最新对方消息。

最终请求受字符上限控制，并在设备端脱敏。后端只接收匿名会话 ID、应用类型、摘要和文本轮次，不接收截图、真实联系人 ID 或聊天标题。

### 5. SuggestionOrchestrator

触发键是“会话 ID + 最新上下文指纹”，不是草稿。只有出现新的对方消息、上下文发生实质变化、失败后的显式重试，或用户点击刷新时才请求。用户开始输入后保留已有建议，不取消、不重新请求；点击建议只写入输入框，永不自动发送。

没有可用上下文时，候选栏显示简短权限状态和开启入口，不把草稿伪装成聊天理解结果。普通 RIME 输入完全离线，AI/OCR/网络失败不得阻塞或重启键盘。

## 低延迟与渐进展示

后端 provider 接口改为异步逐条产出。MiMo 请求使用其 OpenAI 兼容流式接口，以受约束的逐行格式依次生成 `natural`、`gentle`、`boundary`；解析器在每条完整且通过长度/风格校验后立即发出 SSE `suggestion` 事件，不等待第三条。若流式格式损坏或主模型失败，只进行一次有界降级，不重复已发出的建议。

Android 网络层通过回调/Flow 逐条交付，候选栏收到第一条后立即替换 loading，后续追加到最多三条。去掉固定 600ms 草稿防抖；无障碍快照自身使用短时间稳定窗口去除界面抖动。目标是：已有 UI 文本上下文时第一条建议 P95 不超过 2 秒，OCR 路径 P95 不超过 4 秒。

长期摘要更新不进入首条建议的关键路径。建议完成后，设备可以接受后端的可选 `memory` 事件并写回本地；摘要失败不影响本次建议。

## API 兼容性

保留 `POST /v1/ai/suggestions:stream`。`SuggestionRequest` 新增可选字段：

- `conversation_id`：客户端 HMAC/临时匿名会话 ID；
- `memory_summary`：受限长度的脱敏摘要；
- `trigger`：`context_change` 或 `manual_refresh`。

旧客户端仍可发送原字段。服务端继续拒绝任何 screenshot/image 字段。SSE 保持 `meta`、最多三条 `suggestion`、`done/error`，可在建议之后增加可选 `memory`；Android 必须忽略未知事件以保持向前兼容。

## 默认值与权限体验

- `auto_suggest=true` 是客户端和服务端设置默认值。
- 首次安装向导明确说明 AI 已默认开启，并将“启用聊天理解权限”作为 AI 可用的必要步骤。
- 用户跳过权限仍可使用完整离线输入，但 AI 区显示“开启聊天理解后生成回复”，不发送草稿。
- 用户关闭 AI 后立即停止 CaptureSession、清空内存快照并隐藏建议；本地记忆保留与否由独立的保存开关控制。

## 错误与安全

- 会话身份置信度低：只用临时记忆。
- 权限失效：停止生成并显示可恢复状态。
- OCR 失败：若 UIA/无障碍文本不足则不生成。
- 网络/模型失败：保留键盘和已有建议，提供手动刷新，不无限自动重试。
- 敏感场景：清空快照，不读取记忆，不调用后端。
- 服务端日志：不记录正文、摘要、验证码、Token、完整手机号或联系人信息。

## 验收标准

1. 干净安装后 RIME 私有目录包含完整方案；全拼和拼音 9 键可在真实微信输入中文。
2. 未开启无障碍/录屏权限时，输入草稿不会产生 AI 网络请求。
3. 新对方消息只触发一次请求；输入 20 个字符不会增加请求次数。
4. 三条建议按到达顺序逐条展示，第一条无需等待另外两条。
5. 切换两位联系人不会混用最近消息或摘要；低置信度会话不写入长期记忆。
6. 本地记录加密、最多 100 条、30 天过期，单会话和全部删除有效。
7. 密码、支付、银行与系统安全界面证明零采集、零请求。
8. 网络和 AI 故障时中文输入、候选学习、9 键与符号键盘正常工作。
9. 后端单测覆盖流式分片、部分成功、模型降级、重复抑制和可选记忆事件。
10. Android 真机覆盖微信、QQ、企业微信、钉钉、飞书、WhatsApp、Telegram、Discord，并记录首条建议耗时。
